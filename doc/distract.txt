1. INTRODUCTION                                         *distract-introduction*

distract.nvim draws small animated companions — a cat, a crab, a sun — that
react to what you are doing in the editor. They walk when you move, sprint when
you type, and curl up and sleep when you stop.

Sprites are drawn procedurally rather than stored as pixel art. Each state is a
pose function sampled along a curve, and volume comes from shading each shape as
a lit hemisphere, so the animation is smooth by construction and every state has
its own art.

==============================================================================
2. REQUIREMENTS                                         *distract-requirements*

    Neovim 0.9 or newer, with truecolor (`:set termguicolors`).

The |distract-overlay| backend additionally needs a Rust toolchain to build its
engine, or a prebuilt binary. See |distract-overlay|.

==============================================================================
3. SETUP                                                       *distract-setup*

>lua
    require("distract").setup()
    -- then
    vim.cmd("DistractStart")
    vim.cmd("DistractSpawn cat")
<
`setup()` is optional; the first command calls it for you with defaults.

==============================================================================
4. CONFIGURATION                                              *distract-config*

>lua
    require("distract").setup({
      backend = nil,           -- unset picks the best this terminal can draw
      fps = 30,                -- simulation rate
      idle_timeout_ms = 5000,  -- quiet time before an `idle` event fires
      debounce_ms = 50,        -- minimum gap between repeats of one event
      cell_width = nil,        -- overlay only, see |distract-overlay|
      cell_height = nil,       -- overlay only, see |distract-overlay|
      max_sprite_colours = 128,    -- palette cap for imported art
      max_highlight_groups = 4096, -- ceiling on live sprite highlight groups
      position = {             -- placement, see |distract-position|
        anchor = "auto",
        ground = "screen",
        parallax = { per_unit = 0.0, min = 0.4, max = 1.6 },
      },
      assets = {},             -- extra or replacement manifests
    })
<
                                                    *distract-config-backend*
backend~
    Which renderer to use. See |distract-backends|. Left unset, a terminal that
    answers the graphics protocol query gets `"kitty"` and everything else gets
    `"halfblock"`. Naming one here or with `:DistractBackend` always wins, and
    is remembered across later `setup()` calls that name none.

                                        *distract-config-max_sprite_colours*
max_sprite_colours~
    How many colours imported art (see |distract-gif|) is reduced to before the
    half-block renderer draws it. Every distinct foreground/background pair
    becomes a Neovim highlight group, and a GIF frame carries up to 256 colours
    per frame. Procedural art is already drawn from a small palette and is left
    at full fidelity. `kitty` and `overlay` are unaffected. Defaults to 128.

                                      *distract-config-max_highlight_groups*
max_highlight_groups~
    Ceiling on how many sprite highlight groups stay defined at once. Groups
    belong to the asset that asked for them; on reaching the ceiling the least
    recently drawn asset's groups are cleared and its cached frames dropped.
    The asset being drawn is never evicted. Defaults to 4096.

                                                        *distract-config-fps*
fps~
    Simulation and redraw rate for the in-terminal backend. The overlay engine
    runs its own loop at 60 FPS and skips frames entirely when nothing is
    moving.

                                             *distract-config-idle_timeout_ms*
idle_timeout_ms~
    How long the editor must be quiet before an `idle` event is dispatched.
    Applies to both backends.

                                                 *distract-config-debounce_ms*
debounce_ms~
    Minimum interval between repeats of the same event name. Throttling is per
    event name, so `typing` and `moving` — which both fire on every keystroke in
    insert mode — do not cancel each other out.

                                                   *distract-config-position*
position~
    Where entities are placed and what they stand on. See
    |distract-position|.

                                                     *distract-config-assets*
assets~
    A table of `name = manifest`. Anything set here takes precedence over the
    built-in `cat`, `crab` and `sun`. See |distract-manifests|.

------------------------------------------------------------------------------
4.1 POSITION                                                *distract-position*

>lua
    require("distract").setup({
      position = {
        anchor = "auto",   -- "auto" | "bottom" | "top" | "free" | { x=, y=, z= }
        ground = "screen", -- "screen" | "text"
        parallax = { per_unit = 0.0, min = 0.4, max = 1.6 },
      },
    })
<
Every field can be overridden for one spawn:
>lua
    require("distract").spawn("cat", { anchor = "top", ground = "text", z = 2 })
<
                                                    *distract-position-anchor*
anchor~
    Where an entity starts.

        "auto"      Decided by the asset, and failing that by what the entity
                    can physically do. An asset may declare an `anchor` of its
                    own -- the sun declares `"top"`, because a sun belongs in
                    the sky -- and otherwise something bound by gravity starts
                    on the floor while something that drifts starts in the
                    middle of the screen. This is why the cat and the crab walk
                    along the bottom. See |distract-locomotion| and
                    |distract-manifest-anchor|.
        "bottom"    Standing on the floor.
        "top"       At row zero. It still owns the floor it will land on, so a
                    falling entity has somewhere to land.
        "free"      The middle of the screen.
        { x=, y=, z= }
                    An explicit position, in terminal cells. `z` is
                    dimensionless.

    `x=`, `y=` and `z=` passed to a single spawn override the anchor.

                                                    *distract-position-ground*
ground~
    Which floor an entity stands on.

        "screen"    The bottom of the usable screen: the screen height less
                    'cmdheight' and the statusline. Recomputed when the window
                    is resized and when either option changes.
        "text"      The screen row the last line of the buffer starts on, so
                    entities walk along the end of your file. Recomputed as the
                    text and the scroll position change.

    A wrapped or folded line occupies screen rows that no line number maps to.
    Where the last line's row cannot be addressed, the text floor falls back to
    the screen floor rather than guessing.

                                                  *distract-position-parallax*
parallax~
    Depth, expressed as a factor derived from `z`:
>
        scale = clamp(1 + z * per_unit, min, max)
<
    The factor damps both `vx` and `vy` and scales the drawn sprite, so a
    distant thing is smaller and drifts more slowly in both axes. Because the
    sprite is smaller, the floor and the screen edges measure the smaller
    footprint too.

    `per_unit` defaults to `0.0`, which makes every factor exactly 1. Parallax
    is off until you ask for it, and no existing configuration changes
    behaviour.

    A backend that cannot scale a sprite cannot show depth. There, `z` sets
    draw order only, and the degradation is reported once rather than applied
    silently. See |distract-capabilities|.

                                                         *distract-position-z*
z~
    Depth. Dimensionless, and it means two things at once:

        - Draw order. A spawned `z` overrides the manifest's `z_index`.
        - Parallax, as above.

------------------------------------------------------------------------------
4.2 POSITIONING SCOPE                                    *distract-positioning*

Which rectangle sprites may move in, what they must not cover, and where their
surfaces sit in Neovim's float stacking.

>lua
    require("distract").setup({
      positioning = {
        scope = "editor",
        exclude_floating = true,
        exclude_filetypes = {
          "toggleterm", "lazy", "TelescopePrompt", "fzf", "help",
        },
        z_index_offset = 40,
      },
    })
<
                                                    *distract-positioning-scope*
scope~
    `"editor"`   The whole editor grid. The default, and what every release so
                 far has used.
    `"window"`   The current window, including its gutter.
    `"buffer"`   The current window's text area, with the sign, number and fold
                 columns taken off. This is the one to pick if you want a pet
                 that lives in the file you are editing.
    `"absolute"` The editor grid with no exclusions at all: sprites may cover
                 anything, including floating windows.

    Wrapping, bouncing and clamping all measure against this rectangle, on both
    backends: the overlay is told about it over IPC, because only the editor can
    see where a window's text area is.

                                         *distract-positioning-exclude_floating*
exclude_floating~
    Hide a sprite for as long as its footprint would cover a floating window. An
    LSP hover or a completion menu is what you are reading; a sprite over it is
    worse than no sprite. On by default.

                                        *distract-positioning-exclude_filetypes*
exclude_filetypes~
    Windows whose contents a sprite must never cover, floating or not. Setting
    this REPLACES the default list rather than adding to it.

                                           *distract-positioning-z_index_offset*
z_index_offset~
    Neovim float stacking for sprite surfaces. The default of 40 puts a sprite
    below LSP hovers and completion menus, which sit at 50 and above.

    This is not |distract-position-z|. That one is depth and parallax; this one
    is what draws over what. Two different numbers.

------------------------------------------------------------------------------
4.3 INSTANCE VISIBILITY                                   *distract-visibility*

                                                  *distract-restrict_to_instance*
restrict_to_instance~
    Hide sprites while this Neovim instance does not have focus, and show them
    again when it regains it. On by default.

    A companion belongs to the editor it was spawned from. Both renderers draw
    somewhere the editor does not own — the overlay is a separate always-on-top
    window, and an in-terminal float survives whatever is in front of the
    terminal — so an unfocused instance used to keep painting over whatever you
    had switched to, including a second Neovim.

    The simulation keeps running while hidden. Hiding is a drawing decision and
    never a simulation one, for the same reason a settled world is still
    stepped: an entity halfway through a screen wrap must not be stranded at the
    edge until you come back.

    Set it to `false` to keep drawing regardless, which is what a standalone
    desktop animation wants — the overlay engine is useful without Neovim in
    front of it.

5. COMMANDS                                                 *distract-commands*

                                                                *:DistractStart*
:DistractStart          Start the engine for the current backend.

                                                                 *:DistractStop*
:DistractStop           Stop the engine and remove every entity.

                                                               *:DistractToggle*
:DistractToggle         Start if stopped, stop if running.

                                                                *:DistractSpawn*
:DistractSpawn [asset] [opts]
                        Spawn an entity. Defaults to `cat`. Completes on the
                        available asset names. `opts` are `key=value` pairs:
                        `x=`, `y=` (terminal cells), `z=` (depth),
                        `anchor=auto|bottom|top|free` and `flip_x=true|false`.
                        An unrecognised option is reported and skipped; the
                        entity still spawns. See |distract-position|. >
                            :DistractSpawn crab x=10 y=5 flip_x=true
                            :DistractSpawn sun anchor=top z=-3
<

                                                               *:DistractAction*
:DistractAction {action} [target]
                        Trigger a custom action. `target` may be an entity id or
                        an asset name; omit it to affect everything. Built-in
                        actions are `jump`, `yawn` (cat), `clip`, `burrow`
                        (crab) and `eclipse`, `flare` (sun).

                                                                *:DistractClear*
:DistractClear          Remove every entity. The engine keeps running on both
                        backends, so a later `:DistractSpawn` works without
                        restarting.

                                                               *:DistractStatus*
:DistractStatus         Report every live entity, its state and its position.

                                                              *:DistractBackend*
:DistractBackend [name] Show the current backend and what it can do, or switch
                        to `name`. Switching restarts the plugin if it was
                        running. Entities do not carry over between backends.
                        See |distract-capabilities|.

                                                                *:DistractBuild*
:DistractBuild          Build the overlay engine binary in the background. Only
                        needed for the |distract-overlay| backend.

==============================================================================
6. BACKENDS                                                 *distract-backends*

Three renderers are available: `halfblock`, `kitty` and `overlay`. All three run
the same state machine, the same physics and the same art, and place a sprite in
the same cells.

------------------------------------------------------------------------------
6.1 halfblock                                              *distract-halfblock*

The default. Draws sprites inside Neovim using the Unicode half-block
characters, two sprite pixels per terminal cell, coloured with truecolor
highlights.

Requires `termguicolors`. Works over SSH, inside tmux, and in any terminal that
supports 24-bit colour. Each entity gets its own small floating window, which is
what lets the editor show through everywhere the sprite is not.

------------------------------------------------------------------------------
6.2 kitty                                                      *distract-kitty*

Draws real RGBA sprites through the terminal graphics protocol, so transparency
is per pixel rather than per half-block cell and the terminal resamples the
image when depth calls for it.

A sprite occupies exactly the cells it would in `halfblock`: 24x16 sprite
pixels are 24 columns by 8 rows either way. The extra fidelity is inside that
rectangle, so placement, |distract-position-ground| and |distract-units| do not
change when you switch to it.

Requirements, all of which fail closed to `halfblock`:

    - A terminal that answers the protocol's `a=q` query. Confirmed against
      kitty and Ghostty; `ghostty` and `wezterm` resolve to this backend.
    - `termguicolors`. A placeholder cell carries its image id in its
      foreground colour, and without truecolor Neovim rounds that id to the
      nearest palette entry.

The backend offers itself automatically when `$TERM`, `$TERM_PROGRAM` or
`$KITTY_WINDOW_ID` already names a terminal known to support it. Being offered
is not being selected: >vim
    :DistractBackend kitty
<
Asking for it by name on any other terminal sends the query and waits up to
200ms for an answer. A session that never asks for kitty never sends anything.

Note: Ghostty answers the query but sets no `$KITTY_WINDOW_ID`, which is why
the environment is a shortcut rather than the test.

------------------------------------------------------------------------------
6.3 overlay                                                  *distract-overlay*

Runs a separate Rust process that opens a transparent, always-on-top,
click-through window over your whole screen and draws sprites on the GPU.

Build it first: >
    :DistractBackend overlay
    :DistractBuild
<
or build it yourself: >
    cargo build --release --manifest-path <plugin>/engine/Cargo.toml
<
A binary placed at `engine/bin/distract-engine` is also picked up, which is
where a release archive should be unpacked.

                                                        *distract-cell-size*
Cell size~

The overlay positions entities in screen pixels, but Neovim measures everything
in terminal cells. Converting between them needs the terminal's cell size in
pixels, and there is no portable way to ask for it from inside Neovim.

Resolution order:
    1. `cell_width` / `cell_height` from |distract-config|, if set.
    2. The terminal's own answer to the `CSI 16 t` query. kitty, WezTerm,
       Ghostty, foot and iTerm2 answer it; most others ignore it.
    3. A 10x20 default.

If entities do not line up with your editor — most likely on a HiDPI display,
where a real cell is closer to 16x36 — measure your cell size and set it: >lua
    require("distract").setup({
      backend = "overlay",
      cell_width = 16,
      cell_height = 36,
    })
<
The sprite scale follows `cell_width`, so overlay sprites come out the same
apparent size as the same sprite drawn in the terminal.

                                                        *distract-x11*
X11~

The overlay backend refuses to start on X11. Click-through is what stops a
fullscreen always-on-top window from swallowing every mouse click on your
desktop, and it is not available there. Use `halfblock`, or a Wayland session.

------------------------------------------------------------------------------
6.4 CAPABILITIES                                        *distract-capabilities*

Not every backend can draw everything. What each one can do is a table rather
than a set of special cases, so a feature degrades in a stated way instead of
silently doing nothing:

    backend      sprite scaling   transparency   z
    ---------    --------------   ------------   -----------------
    halfblock    no               per cell       draw order
    kitty        yes              per pixel      draw order + parallax
    overlay      yes              per pixel      draw order + parallax

`:DistractBackend` with no argument prints this for the running backend.

Depth needs scaling, so |distract-position-parallax| has no meaning on
`halfblock`: a half-block cell is a fixed size and there is no sub-cell
scaling to make a distant sprite smaller. Configuring parallax while running
that backend reports the degradation once and honours draw order only.

7. ASSETS AND MANIFESTS                                    *distract-manifests*

A manifest describes one kind of entity: its states, what each state looks like,
how it moves, and what makes it change state.

>lua
    {
      name = "cat",
      asset_type = "procedural",   -- or "sprite"
      spritesheet = {},            -- see |distract-custom-art|
      initial_state = "idle",
      z_index = 10,
      anchor = "bottom",           -- optional, see below
      states = {
        walk = {
          animation = { frames = { 4, 5, 6, 7 }, fps = 6.0, loop_anim = true },
          physics   = { target_vx = 1.5, wrap_mode = "wrap" },
          transitions = {
            on_event = { typing = "walk_fast", idle = "idle" },
            timeout_ms = 3000,
            on_timeout = "idle",
          },
        },
      },
      custom_actions = {
        jump = { target_state = "jump", duration_ms = 1200, return_state = "idle" },
      },
    }
<
`animation.frames` holds 0-based indices into the asset's frame list, not
positions in the animation. `wrap_mode` is one of `wrap`, `bounce`, `clamp`,
`despawn` or `none`.

                                                  *distract-manifest-wrap_mode*
`wrap` is toroidal, not a teleport: an entity crossing an edge is drawn at both
edges at once, so the half that has left the right side arrives at the left in
the same frame. A sprite leaving a corner is drawn four times. Nothing about
this is configurable — a seam that popped was simply wrong.

`bounce` turns the entity around at the edge and flips which way it faces;
`wrap` deliberately does neither, because continuing in the same direction is
what wrapping means. A pet that should patrol wants `bounce`.

Transition keys: `on_event`, `on_finish`, `timeout_ms` with `on_timeout`,
`on_edge_left`, `on_edge_right` and `on_land` (see |distract-locomotion|).

                                                     *distract-manifest-anchor*
anchor~
    Where this asset belongs, when nothing else has said. One of `"auto"`,
    `"bottom"`, `"top"` or `"free"`; omitting it means `"auto"`.

    A property of the asset rather than of anyone's configuration, in the same
    way `z_index` and `locomotion` are: the built-in sun declares `"top"`,
    because a sun belongs in the sky and `omnidirectional` on its own only says
    it is free to leave the floor.

    An `anchor` in |distract-position| or on a single spawn overrides it. An
    anchor outside the four names above is an error at spawn rather than a
    silent fallback.

------------------------------------------------------------------------------
7.1 Locomotion                                             *distract-locomotion*

`physics.locomotion` says how a state moves: >
    grounded          gravity pulls it onto a floor at `ground_y`
    ballistic         the same, and fires `on_land` when it arrives
    omnidirectional   no gravity and no floor; the paths below apply
<
Omitted, it is derived — `gravity > 0` means `grounded`, anything else means
`omnidirectional`. Every manifest written before the field existed therefore
keeps its exact behaviour.

`on_land` fires once, on the tick a `ballistic` entity's `y` reaches
`ground_y` from above: >lua
    jump = {
      physics = { gravity = 0.4, jump_impulse_y = -6, locomotion = "ballistic" },
      transitions = { on_land = "idle" },
    }
<
Without it a jump has to guess when it is over — the built-in cat returns
through `on_finish`, so it lands when the art runs out rather than when it
touches the ground.

`physics.ground_y` is in terminal cells, like every other manifest position.
Omitted, the floor is wherever the entity was when it entered the state, which
is what makes a jump return to the ground it left.

A manifest may set `locomotion` at the top level as the default for every
state, which is usually what you want: only one of the cat's six states leaves
the ground.

                                                        *distract-capabilities*
An asset can declare which classes it is allowed to use: >lua
    capabilities = { locomotion = { "grounded", "ballistic" } },
<
Checked once when the manifest loads, across every state at once — never per
frame. A violation is reported and the spawn produces nothing, on both
backends. Omitted, all three are allowed, so no manifest written before this
existed can newly fail.

The built-ins declare `cat` = grounded, ballistic; `crab` = grounded; `sun` =
omnidirectional.

Two constraints hold whether or not you declare capabilities, because both
describe states that would silently do nothing:

    - `omnidirectional` with `gravity` set. Gravity brings a floor, so the
      state would clamp to a floor it claims not to have.
    - `orbital`, `lissajous` or `bezier` on a state that is not
      `omnidirectional`. Those paths write `x` directly, and both engines skip
      paths entirely under gravity.

------------------------------------------------------------------------------
7.2 Paths                                                       *distract-paths*

`physics.path_type` overrides position on top of the velocity integration,
relative to where the entity was when it entered the state. One of: >
    linear      no override at all; velocity alone (the default behaviour)
    sine        y = base_y + sin(freq_y*phase) * amp_y
    orbital     x = base_x + cos(freq_x*phase) * amp_x
                y = base_y + sin(freq_y*phase) * amp_y
    lissajous   x = base_x + sin(freq_x*phase + phase_delta) * amp_x
                y = base_y + sin(freq_y*phase) * amp_y
    bezier      cubic over `points`, phase looping over [0,1]
<
Parameters live in `physics.path_params`: >lua
    physics = {
      path_type = "lissajous",
      path_params = {
        freq = 1.2,         -- phase advance, radians per second (default 1)
        freq_x = 3.0,       -- x multiplier inside the term (default: freq_y)
        freq_y = 2.0,       -- y multiplier inside the term (default 2)
        amp_x = 20.0,       -- sprite pixels (default: amp_y)
        amp_y = 10.0,       -- sprite pixels (default 4)
        phase_delta = 0.78, -- radians, `lissajous` x axis only
        points = {          -- `bezier` only: four {x, y} control points,
          { 0, 0 },         -- in sprite pixels relative to the spawn point
          { 20, -18 },
          { 40, 18 },
          { 55, 2 },
        },
      },
    }
<
One phase drives every axis, and per-axis frequency multiplies inside the
trigonometric term rather than in the phase advance — otherwise `lissajous`,
whose whole point is two axes at different rates, would apply its frequency
twice.

A path is skipped entirely when `gravity` is set: an override that writes `y`
fights the floor. `path_amplitude` and `path_frequency` are the older names for
`amp_y` and `freq_y` and still work.

------------------------------------------------------------------------------
7.3 Units                                                       *distract-units*

Positions and velocities are in *sprite pixels*, and velocities are per frame at
60 FPS. One sprite pixel is one terminal cell wide and half a terminal cell
tall — exactly what the half-block renderer draws.

Both backends convert from that same unit, so one manifest describes one
behaviour everywhere: the in-terminal backend converts to cells, and the overlay
multiplies by its pixels-per-sprite-pixel scale (see |distract-cell-size|).

`gravity` and `jump_impulse_y` are in the same unit. `path_amplitude` is in
sprite pixels and defaults to 4.

------------------------------------------------------------------------------
7.4 Custom art                                              *distract-custom-art*

Set `spritesheet.path` to use your own image instead of the generated sprites: >lua
    spritesheet = {
      path = "/path/to/sheet.png",
      frame_width = 32,
      frame_height = 32,
      columns = 8,
      rows = 1,
    }
<
Animated GIFs are also accepted, on every backend; see |distract-gif|.

A still spritesheet in any other format is decoded by the overlay engine only.
In the terminal the asset has no art, which is reported once.

Limits, so a large asset fails with a message rather than exhausting memory:
    - 1024 px per side, per drawn frame
    - 512 frames
    - 256 MiB decoded in total

A path that does not exist, or an image that cannot be decoded, is reported as
an error rather than silently falling back to the generated art.

Note that `animation.frames` indices must exist in your sheet. A four-frame
sheet with a manifest referencing frame 28 wraps modulo four, so several states
end up drawing the same picture.

------------------------------------------------------------------------------
7.5 GIF assets                                                     *distract-gif*

A manifest whose `spritesheet.path` ends in `.gif` is drawn by every backend:
per-pixel on |distract-kitty| and |distract-overlay|, in half-blocks on
|distract-halfblock|. Nothing else in the manifest changes. >lua
    spritesheet = {
      path = "assets/cat_walking_1.gif",  -- relative paths are plugin-relative
      frame_width = 32,                   -- sprite pixels
      frame_height = 24,
    }
<
Decoding in the terminal is pure Lua — GIF87a and GIF89a, LZW, interlacing,
local palettes, the transparency index and disposal methods 0-3 — so no engine
binary and no external process is involved.

`frame_width` and `frame_height` are the size the sprite is *drawn* at, in
sprite pixels (|distract-units|), on every backend. A GIF authored at screen
size is resampled to them. Without them the source size is the sprite size, and
a canvas past the budget is refused with a message naming the two fields.

Timing follows `animation.fps` when a state declares one. A state that declares
none is timed by the delays stored in the file, which is the rate the animation
was authored at. Both backends apply that precedence.

Imported art is reduced to |distract-config-max_sprite_colours| before the
half-block renderer draws it, because every distinct colour pair there becomes a
Neovim highlight group. `kitty` and `overlay` take it at full colour.

==============================================================================
8. EVENTS                                                     *distract-events*

Editor activity is translated into these event names, which manifests match in
`transitions.on_event`:

    typing      TextChanged, TextChangedI
    moving      CursorMoved, CursorMovedI
    scrolling   WinScrolled
    idle        no activity for `idle_timeout_ms`

Every event carries the cursor's screen position. An entity that picks up a
moving state in response will turn to face the cursor, so it looks like it
noticed where you are working.

==============================================================================
9. EXTENDING IT                                            *distract-extending*

Three surfaces. Everything a companion knows about your editor arrives through
one of them, and each one works the same way on all three backends.

------------------------------------------------------------------------------
9.1 PLUGIN HOOKS                                             *distract-plugins*

>lua
    require("distract").register_plugin("my-plugin", {
      on_init = function(world) end,
      on_tick = function(entity, dt) end,
      on_state_change = function(entity, from_state, to_state) end,
      on_collision = function(entity, collision) end,
      on_editor_event = function(event_name, context) end,
      on_draw = function(layers) end,
      on_teardown = function() end,
    })
<
Every hook is optional; an unknown key is refused rather than ignored.

The entity a hook receives is READ-ONLY. Assigning to it raises. That is not
politeness: the in-terminal backends simulate in Lua while `overlay` simulates
in its own process, so a hook that wrote `entity.vx` would move the sprite on
two backends out of three. Changes go through the `world` handle instead:

>lua
    world.backend                       -- "halfblock" | "kitty" | "overlay"
    world.entities()                    -- read-only views of what is alive
    world.request_state(id, state)      -- put an entity into a declared state
    world.apply_impulse(id, vx, vy)     -- add to its velocity
    world.despawn(id)
    world.mark_dirty()                  -- redraw a frame that would be skipped
<
Commands are queued and applied at the top of the next simulated step, so a
hook never observes an entity halfway through its own frame. On `overlay` the
same queue is forwarded over IPC, so one plugin produces one behaviour.

`collision.edge` is `"left"`, `"right"`, `"top"`, `"bottom"` or `"obstacle"`.

`on_draw` receives where every sprite was actually drawn, in terminal cells, on
every backend: `{ id, asset_name, row, col, width, height }`. It is what a
speech bubble or a highlight is built on.

`mark_dirty` matters more than it looks. A settled world is not redrawn — that
is what makes an idle pet free — and that includes whatever a plugin just
changed about it.

A hook that raises is reported once at WARN and its plugin is disabled for the
session. One broken plugin cannot silence the others, and cannot produce a
notification per frame.

Nothing is put on the wire for `overlay` unless a registered plugin actually
subscribes: no plugins means no per-frame traffic at all.

Working examples live in `examples/plugins/` in the repository.

------------------------------------------------------------------------------
9.2 OBSTACLE PROVIDERS                                     *distract-obstacles*

Solid ground and hazards, made out of whatever your editor can see.

>lua
    require("distract").register_obstacle_provider(function(win_id, buf_id)
      return {
        { x = 10, y = 15, width = 40, height = 1, type = "solid_platform" },
        { x = 0,  y = 25, width = 80, height = 1, type = "hazard" },
      }
    end)
<
Rectangles are in terminal cells, the same units the floor is measured in.

    solid_platform  A one-way floor. It catches an entity falling onto it from
                    above and is what a grounded entity walks along; passing
                    upward through it is free, so a jump onto one works.
    hazard          A wall. An entity that reaches one is returned the way it
                    came and turns around.

A grounded state has no gravity to fall under, so which surface it stands on is
resolved every frame: the highest platform under its feet, or the floor. Walk
off the end of a platform and the pet is on whatever is below it.

Providers are called on a debounced cadence — editing, scrolling, window and
buffer changes — and never per tick per entity. A Tree-sitter query per frame is
a performance trap, which is why the contract takes a function.

At most 128 rectangles are used, reported once if a provider returns more. A
malformed rectangle is refused with a message rather than reaching the physics.
A provider that raises is skipped; the others still contribute.

Providers are collected in Neovim and pushed to whichever engine is running.
Neither engine goes looking for its own, for the same reason neither measures
its own floor: only the editor can see the buffer.

==============================================================================
10. TROUBLESHOOTING                                  *distract-troubleshooting*

Sprites are the wrong colour, or invisible~
    Truecolor is required: >vim
        :set termguicolors
<
Overlay entities do not line up with the editor~
    Set `cell_width` and `cell_height`. See |distract-cell-size|.

The overlay refuses to start~
    Either the engine is not built (`:DistractBuild`), or you are on X11, where
    click-through is unavailable. See |distract-x11|.

`:DistractStatus` says nothing is alive but I can see something~
    Run `:DistractStop` then `:DistractStart`. If it recurs, please report it.
